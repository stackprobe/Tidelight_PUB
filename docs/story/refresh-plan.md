# 和風ファンタジー改稿計画

## 維持する骨格

作品名『潮待ちの灯』、港町・岬の灯台・干潮の石段、幼なじみとの再会、12パート・10経路・6結末を維持する。選択肢は関心と役割を選ぶものとし、正解の押しつけや失敗結末は設けない。

## 作業順

1. 世界の仕組み、三人の動機と口調、経路別の時間・知識を確定する。
2. 各パートの会話・地の文を改稿前の約3倍へ増量する。情景、対話、作業中の小さな発見を加え、同じ説明の反復で水増ししない。
3. ミオ・レンの立ち絵を和装で描き直し、サヨを追加する。頭身、頭頂と足元、画風を統一し、ミオの表情差分を制作する。背景も世界観に合わせる。
4. 設定の正本とゲームデータ、人物一覧、パート要約、画像制作記録、作品紹介を同期する。
5. 本文量、分岐、全結末、保存再開、人物の登退場、画像寸法と透過を検証する。画像を目視確認し、変更をコミットする。

## 改稿の軸

「帰ってくる者のために、灯を守る・道を測る・名を呼ぶ」。不思議は実在するが、何でも解決する力ではない。各人の異なる仕事を、主人公が手伝う一日の物語。

ミオは灯守見習い、レンは潮図師見習い、サヨは潮の祠の名預かり。帰り灯は生者の船のための道標、祠の送り火は死者のための灯で、混同しない。術が働いても、潮位・風・船の現物確認が必要。

## 分量の測り方

各パートの dialogue.text のUnicode文字数の合計で比較する。改稿前の文字数は parts.md に記録し、各パートおおむね2.8〜3.5倍を目安とする。結末文と選択肢、演出ステップは数えない。セリフは短いウィンドウに分け、1ウィンドウへ長文を詰め込まない。

## 互換性

既存パートID、既存ステップID、分岐先、結末IDを保持する。追加の会話は新しいIDを割り当てる。古いセーブは保存したステップから改稿後の物語を再開するため、全編の刷新を読む場合は「はじめから」を推奨する。

## 実施結果

- 世界観・開始時点・3人の設定・全12パートを改稿し、実行データへ反映した。本文は各2.88〜3.49倍、全体3,213字から10,652字（約3.32倍）、236会話ウィンドウ。
- ミオ・レンを描き直し、サヨを追加。ミオの笑顔と背景2点も制作した。保存先、頭身・透過・表情位置の確認と生成指示は assets.md・image-prompts.md に記録。
- 従来の全ステップIDと分岐先を保持したことを改稿前データと照合。全10経路・6結末・全236会話を含む280保存地点の再開、文字送り、人物表示の整合性を自動テストで確認。データ・画像規格の検証は警告0件。
- 画像単体・立ち絵比較を目視確認。ブラウザでの実画面確認のみ、内蔵ブラウザのローカル接続タイムアウトとChromeの現在URL判定失敗で未実施。ツールが停止したため、以降のUI操作は行っていない。
