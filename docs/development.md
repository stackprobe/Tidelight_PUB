# 開発・運用ガイド

和風ファンタジーの港町を舞台にした分岐アドベンチャーです。公開パートは12件、登場人物は灯守見習いのミオ、潮図師見習いのレン、祠の名預かりサヨの3人。帰り灯・船迎え・石段の調査から6種類の結末へ分岐します。背景と立ち絵は Canvas 2D で描画し、メッセージと操作ボタンは HTML で重ねます。

港町と分岐の骨格を残し、各パートを改稿前の約2.9〜3.5倍に増量しました（本文合計10,652字、236会話ウィンドウ）。潮霧の中で帰る船を、灯と潮図と結び糸で迎える一日の物語です。[改稿方針](story/refresh-plan.md)、[各パートの分量と接続](story/parts.md)を記録しています。既存セーブは利用できますが、刷新した冒頭から読む場合は「はじめから」を選んでください。

## 起動と配置

ローカルで遊ぶ場合は、`DocRoot/index.html` をダブルクリックしてブラウザで開きます。ファイルからのプレイでは進行状況を保存せず、ページを開き直すとはじめからになります。

公開時と同じ Cookie 保存を手元で確認する場合は、このフォルダから次を実行し、ブラウザで `http://127.0.0.1:8000/` を開きます。

```sh
node tools/serve.mjs
```

公開時は `DocRoot/` の中身だけを設置先へコピーします。HTML・JS・画像は相対 URL で読み込むため、サイトのルートや任意のサブディレクトリで使えます。ディレクトリ URL は末尾のスラッシュ付きで配信するか、`index.html` を明示してください。タイトルの「戻る」は設置先の親 URL (`../`) へ移動します。

## 操作

- スマートフォンは縦持ち向けです。PC でも同じ 9:16 のゲーム画面が中央に表示されます。背景や「次へ」をタップすると会話が進みます。長文は本文欄をスクロールして読めます。
- 選択肢は対応するボタンをタップまたはクリックします。PC では Enter / Space で会話を進め、矢印キーと Enter、または 1 / 2 で選択できます。
- セリフは JavaScript で約35msごとに1文字ずつ表示します。表示途中のタップ・クリックや Enter / Space は全文表示になり、もう一度操作すると次へ進みます。
- HTTP/HTTPS で開いたときは、台詞・選択肢・結末で入力を待つ時点で、自動的に Cookie へ保存します。タイトルの「つづきから」で再開できます。Cookie は設置先のディレクトリごとに管理し、保存位置と直近最大12件の選択を保持します。

## シナリオの追加

1. [執筆資料の入口](story/README.md)から世界観・開始時点・登場人物の設定とパート接続を確認し、接続元と接続先の実際のパートを読みます。執筆用設定の正本は `docs/story/` の Markdown です。
2. `DocRoot/data/parts/` にパートのデータファイルを作成します。既存の `part_001.js` を雛形に使い、`StoryWalkScenario.register(...);` の中を JSON 形式で編集します。公開済みのパート ID とステップ ID はセーブの再開に使うため、維持してください。
3. [画像サイズ規格](story/assets.md)に従い、背景は800×1422px、通常倍率の人物は高さ1024pxへ整えてから `DocRoot/images/` に置き、背景は `data/backgrounds.js`、立ち絵はキャラクター定義の `visual.expressions` に登録します。各パートの場面は独立して組み立てます。冒頭で背景を指定すると、分岐時に前の背景からクロスフェードします。
4. `data/manifest.js` で公開パートに `published` とデータファイルの相対パスを設定します。追加予定は `planned` として登録できます。パート末尾には登録済みパートへの選択肢を2件指定する `choice`、または結末名と説明を `text` に記述する `end` を置きます。結末では自動保存し、「タイトルへ」で戻れます。
5. 設定を追加・修正した場合は関連する `docs/story/` の Markdown を更新し、パートの内容・接続・公開状態を変更した場合は `docs/story/parts.md` も更新します。
6. このフォルダで `node tools/validate.mjs` を実行します。形式・参照・画像ファイルの存在を検証し、到達性・循環や一部の画像規約を確認します。設定や台詞の意味、表情差分の位置は人手で確認します。

演出時間はパートの `duration` でミリ秒単位で設定できます。省略時は背景 800ms、登退場 600ms、表情 300ms、選択肢の出現 400ms です。

## 執筆用設定と実行用データ

[docs/story/README.md](story/README.md) を入口に、世界観・用語・時系列、物語開始時点、登場人物の固定設定、パート一覧と接続を Markdown で管理します。追加・修正の方法も同資料に記載しています。別チャットでの作業時も `AGENTS.md` からこの入口を参照します。

`DocRoot/data/world.js` は作品タイトル・サブタイトル・タイトル背景、`DocRoot/data/characters/*.js` は ID・表示名・立ち絵と表情など、実行に必要な情報だけを保持します。背景・会話・選択肢は各パートの `steps` で指定します。執筆用 Markdown はゲームから読み込まず、公開先への配置も不要です。

設定の変更は既存の台詞や展開に自動反映されません。設定資料と実際のパートの整合性は執筆・修正時に確認します。`node tools/validate.mjs` と起動時の検証は実行用データを対象とし、Markdown の内容は検証しません。プレイヤーの進行状況は引き続き Cookie に保存します。

## イラスト

内蔵 ImageGen で、和装のミオ・レン・サヨと、朝の港・夕暮れの灯楼を制作しました。立ち絵は同じ水彩と鉛筆の画風、約7〜7.5頭身に統一し、縦横比と透過を保って480×1024pxへ整えています。表情差分は仕草や体の向きも含む全身画像として差し替えます。ミオの笑顔は片手を軽く口元へ寄せ、体を少し斜めにしたポーズです。[立ち絵比較](story/characters-preview.png)で3人を確認できます。

[ミオの通常・笑顔比較](story/mio-expressions-preview.png)でポーズ差分を確認できます。表情差分では、同一人物の特徴と画面内の基準を保ちながら、感情に合う手や体の動きを付けます。

背景は800×1422px。背景・人物とも、元画像を約90％に縮小して想定描画サイズになる寸法で保存する規格です。ゲーム内の表示サイズを90％に小さくする意味ではありません。保存先・縮小方法・目視確認の記録は [画像サイズ規格と制作記録](story/assets.md)、最終生成指示は [画像プロンプト](story/image-prompts.md)を参照してください。

## 動作確認コマンドと既存の確認記録

`node tools/test-story.mjs` で実際のローダー・ゲーム進行・Cookie 保存処理を簡易 DOM と描画アダプター上で実行し、全10経路・6結末、全236会話を含む280保存地点の再開とタイトル復帰を確認しました。文字送り、途中操作での全文表示、タイマー停止、再開後の全文保持も検証します。話者の立ち絵が表示中であること、同じ位置に人物が重ならず最大2人に収まることも確認します。

背景・立ち絵の画像単体と、並べた人物の頭身・足元を目視確認しました。改稿時のブラウザ画面の目視確認は、内蔵ブラウザのローカル接続タイムアウトと、Chrome操作時の現在URL判定失敗で実施できていません。上記の自動テストはブラウザのレイアウト検証ではありません。

`node tools/validate.mjs` はエラー・警告ともにありません。背景と立ち絵は画像サイズ規格に適合しています。
